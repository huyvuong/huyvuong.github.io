The workflow starts with DRAGEN [DRAY-jen] processing the RNA FASTQs [FAST-kyoos]. / Because this is RNA and not DNA, / we face the challenge of variable coverage due to differential gene expression, / as well as RNA editing. / To extract a reliable germline fingerprint, / we enable DRAGEN's [DRAY-jenz] somatic [so-MAT-ik] variant calling mode, / which accurately captures variants at as low as 5% variant allele frequency. / We take the resulting VCFs [V-C-Fs] / and pass them into Picard's [pih-CARD] CrosscheckFingerprints tool, / which compares the genetic signatures / and outputs a pairwise matrix of LOD [L-O-D] scores. / The entire pipeline is orchestrated through Nextflow [NEXT-flow] running on Slurm [slurm], / so it scales horizontally as our sample volume grows.

Three-Zone LOD Decision Rule

LOD scores (log10 likelihood ratio) quantify genetic concordance between sample pairs.

Thresholds calibrated for RNA-Seq coverage variability; more conservative than typical WGS thresholds.

Picard [pih-CARD] provides us with a LOD [L-O-D] score, / which represents the log-ratio of the likelihood / that two samples share the same genetic background / versus being completely distinct. / For our automated decision logic, / we use a three-zone rule. / If the LOD is greater than 5, / we call it a Match. / If it's less than negative 5, / we call it a Mismatch. / The critical part is the gray zone — between negative 5 and positive 5. / Because RNA-seq [RNA-sek] coverage can be spotty, / we treat this range as "Undetermined." / In these cases, / we intentionally defer to the input metadata provided by the source / rather than guessing.

Evaluation Logic

Python module powering the automated QC gate decision


def classify_lod(lod: float) -> str:
    """Categorize LOD score into three-zone decision."""
    if lod > 5:
        return "MATCH"
    if lod < -5:
        return "MISMATCH"
    return "UNDETERMINED"


def evaluate_pair(lod_call: str, same_family_expected: bool) -> str:
    """Cross-reference genetic call against sample manifest.

    Returns POTENTIAL_SWAP when genetics contradict metadata,
    triggering a pipeline halt for manual review.
    """
    if lod_call == "UNDETERMINED":
        return "DEFER_TO_SOURCE"
    if lod_call == "MATCH" and same_family_expected:
        return "CONSISTENT"
    if lod_call == "MISMATCH" and not same_family_expected:
        return "CONSISTENT"
    return "POTENTIAL_SWAP"
classify_lod — Three-zone LOD classification
evaluate_pair — Metadata cross-reference & swap detection
This Python logic drives the final QC [Q-C] gate. / We parse the Picard [pih-CARD] output / and map it against our sample manifest. / The code first categorizes the LOD [L-O-D] score using our three-zone rule. / We then cross-reference that genetic call / against the expected family relationships from our metadata. / If the genetics contradict the metadata — / for instance, if two samples share a family ID / but return a strong "Mismatch" LOD score — / the system outputs "POTENTIAL_SWAP" / and halts the workflow for review.

Appendix: CrosscheckFingerprints Invocation

java -jar picard.jar CrosscheckFingerprints \
    VALIDATION_STRINGENCY=LENIENT \
    INPUT=./data/sample_A.hard-filtered.vcf \
    INPUT=./data/sample_B.hard-filtered.vcf \
    HAPLOTYPE_MAP=hg19_chr.map \
    LOD_THRESHOLD=-5 \
    CROSSCHECK_BY=FILE \
    CALCULATE_TUMOR_AWARE_RESULTS=false \
    NUM_THREADS=6 \
    OUTPUT=sample_A.vs.sample_B.crosscheck_metrics
HAPLOTYPE_MAP: SNP marker panel grouped into LD blocks for genotype concordance
LOD_THRESHOLD=-5: mirrors the mismatch boundary from the three-zone rule
CROSSCHECK_BY=FILE: each VCF treated as one fingerprint group
CALCULATE_TUMOR_AWARE_RESULTS=false: somatic caller used only as a sensitive genotyper, not for tumor/normal LOD adjustment
This is a reference slide: only pull it up if asked how the tool is actually invoked. Walk through HAPLOTYPE_MAP first since that's the input that defines the marker panel and haplotype blocks. LOD_THRESHOLD here is set to -5, which is the mismatch boundary from the three-zone rule on slide 3: Picard itself only distinguishes match/mismatch/ambiguous around this single threshold, and our three-zone logic on top of it adds the +5 match boundary and the defer-to-source behavior in the undetermined band. CROSSCHECK_BY=FILE means each input VCF is treated as a single fingerprint group rather than splitting by read group or library. CALCULATE_TUMOR_AWARE_RESULTS=false is set because the somatic caller upstream is being used purely as a sensitive genotyper to extract germline-fingerprint SNPs from RNA-seq: we're not doing an actual tumor/normal comparison, so the tumor-aware LOD adjustment doesn't apply.
